# SEMA NEXUS — Banco de dados (Oracle)

> **Status:** Core **Implementado** (Issue #3: `V1__core.sql`, `V2__municipios_mt.sql`). Flux (#11), DocIA (#15) e Notificações (#25, P1) **Planejados**.
> **Oracle é obrigatório.** Não usar PostgreSQL, MySQL, H2 ou SQLite em nenhum ambiente, nem em testes.

## Ambiente

| Item | Valor |
|---|---|
| Versão | Oracle Database 23ai Free |
| Imagem | `gvenzl/oracle-free:23-slim-faststart` (tag/digest fixado na Issue #8) |
| Serviço / PDB | `FREEPDB1` |
| URL JDBC (Docker) | `jdbc:oracle:thin:@//oracle:1521/FREEPDB1` |
| URL JDBC (host) | `jdbc:oracle:thin:@//localhost:1521/FREEPDB1` |
| Usuário da aplicação | `APP_USER` (criado pela imagem a partir do `.env`) |
| Versionamento | Flyway, `src/main/resources/db/migration/V<n>__<descricao>.sql` |
| Requisitos | ~2 GB de RAM para o container (host com 8 GB+), ~4 GB de disco, 1ª subida em 1–3 min |

## Convenções

- Tabelas e colunas em MAIÚSCULAS, singular. PK `ID NUMBER GENERATED BY DEFAULT AS IDENTITY`.
- `CRIADO_EM` / `ATUALIZADO_EM` (`TIMESTAMP`); exclusão lógica com `EXCLUIDO_EM` quando aplicável.
- Enums como `VARCHAR2` + `CHECK`. FKs nomeadas `FK_<TABELA>_<REF>`; índices `IX_<TABELA>_<COLUNA>`.
- `spring.jpa.hibernate.ddl-auto=validate`: o Hibernate **não** cria schema; só o Flyway.
- Migration aplicada na `main` nunca é editada; crie uma nova.

- Booleanos usam o tipo nativo `BOOLEAN` do Oracle 23ai (mapeado de `boolean` pelo Hibernate).

## Catálogos (enums)

- **Origem:** Denúncia, Monitoramento, Solicitação institucional, Ação planejada, Análise ambiental.
- **Categoria ambiental (somente fiscalização):** Desmatamento ilegal, Queimada/incêndio, Recursos hídricos, Fauna silvestre, Pesca irregular, Mineração irregular, Resíduos e poluição, Área de preservação permanente.
- **Prioridade:** Baixa, Média, Alta, Urgente.
- **Status:** PENDENTE, EM_TRIAGEM, AGUARDANDO_DISTRIBUICAO, DISTRIBUIDA, EM_ANDAMENTO, AGUARDANDO_CONCLUSAO, FINALIZADA.

## Testes com Oracle

`CoreSchemaOracleTest` (tag `oracle`, Testcontainers com `gvenzl/oracle-free:23-slim-faststart`) sobe o contexto completo com `ddl-auto=validate` e verifica: V1 e V2 aplicadas e não reaplicadas, 142 municípios todos de MT, persistência de setor/usuário/equipe/auditoria e os `CHECK`/UK. Fica fora do `mvn -B verify` padrão; rode com `mvn -B verify -Poracle` (exige Docker). O job agendado de CI é a Issue #23 (P1).
- **Implementado (Issue #5) — base demonstrativa:** `DemoSeedRunner` → `DemoSeedService`, somente nos profiles `demo`/`dev` (nunca com `openapi`, que roda sem banco), idempotente por chave natural (sigla do setor; e-mail do usuário; setor + nome da equipe — só cria o que falta e não altera registros existentes). Lê `src/main/resources/demo/usuarios.json` e grava: 3 setores fictícios (`DEMO-GAB`, `DEMO-FISC`, `DEMO-DOC`), 6 usuários (todos com `DEMO = 1`), 4 equipes de fiscalização fictícias e 6 vínculos de membro. Senhas só como hash BCrypt no JSON; o log informa "seed demonstrativo aplicado / já existente" sem senhas.
- **Planejado (Issue #18):** demandas e documentos fictícios coerentes para a demonstração.
- Reset: `scripts/demo-reset` (Issue #9) — exige confirmação, recusa profiles diferentes de `demo`/`dev`, recria os volumes e recarrega o seed.
